### 其次在dev环境和prod环境打开窗口方式是不一样的

```
// 如果是开发环境，则使用electron-vite的代理服务器加载页面
// 其中is.dev是electron-vite内置的判断开发环境的变量，process.env['ELECTRON_RENDERER_URL']是electron-vite内置的环境变量。
//loadURL是加载本地开发环境的页面，loadFile是加载打包后的生产环境页面。

    if (is.dev && process.env['ELECTRON_RENDERER_URL']) {
      settingsWindow.loadURL(process.env['ELECTRON_RENDERER_URL'] + '/settings.html').then(() => {
        settingsWindow?.show()
      })
    } else {
      // 修改生产环境路径
      settingsWindow.loadFile(join(__dirname, '../renderer/settings.html')).then(() => {
        settingsWindow?.show()
      })
    }
```

## Electron 日志系统

### 安装 electron-log

```bash
npm install electron-log
```

就这一个包，主进程和渲染进程都能用，不用配一堆东西。

### 主进程里使用日志

```ts
// src/main/index.ts 顶部引入
import log from "electron-log/main";

// 初始化（一定要在 app.whenReady() 之前调用）
log.initialize();

// 设置日志文件存放路径（可选，默认在用户目录下）
// Windows: C:\Users\用户名\AppData\Roaming\my-app\logs\main.log
// Mac: ~/Library/Logs/my-app/main.log
log.transports.file.resolvePathFn = () => {
  return join(app.getPath("userData"), "logs", "main.log");
};

// 设置日志文件大小上限（超过自动切割，防止日志文件太大）
log.transports.file.maxSize = 5 * 1024 * 1024; // 5MB

// 然后就可以到处用了
log.info("应用启动了");
log.error("出错了：", someError);
log.warn("警告信息");
log.debug("调试信息"); // debug 级别默认不写文件，只输出到控制台
```

### 渲染进程里使用日志

```ts
// 在 Vue 页面里直接用
import log from "electron-log/renderer";

// 用法和主进程一模一样
log.info("用户点击了按钮");
log.error("接口请求失败：", error);

// 在 Vue 组件里的用法
import { onMounted } from "vue";
import log from "electron-log/renderer";

onMounted(() => {
  log.info("主窗口已加载完成");
});
```

### 让渲染进程的日志也写到文件里

默认情况下，渲染进程的 `electron-log` 只输出到 DevTools 控制台。要让它也写到文件，需要在主进程里做一下配置：

```ts
// src/main/index.ts
import log from "electron-log/main";

// 在 app.whenReady() 里调用
app.whenReady().then(async () => {
  // 初始化日志，这一步会让渲染进程的日志也走主进程的文件写入
  log.initialize({ preload: true });

  // ... 其他初始化代码
});
```

> **大白话解释：** `preload: true` 的意思是"在 preload 脚本里注入日志功能"，这样渲染进程调用 `log.info()` 的时候，实际上是发消息给主进程，由主进程统一写文件。

### 日志文件在哪？怎么让用户发给你？

```ts
// 在主进程里获取日志文件路径
import log from "electron-log/main";

const logPath = log.transports.file.getFile().path;
console.log("日志文件路径：", logPath);
// Windows 输出类似：C:\Users\lij\AppData\Roaming\my-app\logs\main.log
```

你也可以加一个 IPC 接口，让设置页面有个"打开日志目录"按钮：

```ts
// 主进程
import { shell } from "electron";
import log from "electron-log/main";

ipcMain.on("open-log-folder", () => {
  const logPath = log.transports.file.getFile().path;
  // 在文件管理器里打开并选中这个文件
  shell.showItemInFolder(logPath);
});

// 渲染进程（Vue 页面里）
window.api.send("open-log-folder");
```

给不了的话就这样也能看，在用户电脑上看

Start-Process "C:\Program Files\ifts_clients\ifts_clients.exe" -Verb runAs 中间的安装的位置换成你的安装位置，然后就能打开了。

### 日志格式自定义

### 完整的主进程日志配置（直接抄）

```ts
// src/main/index.ts
import { app } from "electron";
import log from "electron-log/main";
import { join } from "path";

// ====== 日志配置（放在文件最顶部，app.whenReady 之前） ======

// 1. 初始化日志系统
log.initialize({ preload: true });

// 2. 设置日志文件路径
log.transports.file.resolvePathFn = () => {
  return join(app.getPath("userData"), "logs", "main.log");
};

// 3. 设置日志文件大小上限
log.transports.file.maxSize = 5 * 1024 * 1024; // 5MB

// 4. 设置日志格式
log.transports.file.format = "[{y}-{m}-{d} {h}:{i}:{s}.{ms}] [{level}] {text}";

// 5. 设置控制台输出格式（开发时用）
log.transports.console.format = "[{h}:{i}:{s}.{ms}] [{level}] {text}";

// 6. 设置日志级别（生产环境只记 info 及以上，开发环境记所有）
log.transports.file.level = "info";
log.transports.console.level =
  process.env.NODE_ENV === "development" ? "debug" : "info";

// ====== 日志配置结束 ======

log.info("========== 应用启动 ==========");
log.info("版本号：", app.getVersion());
log.info("系统：", process.platform, process.arch);

app.whenReady().then(() => {
  log.info("应用 ready，开始创建窗口...");
  createWindow();
});
```

## 自动更新（electron-updater）

### 2.1 整体流程先搞懂

自动更新的核心流程是这样的：

```
1. 你开发完代码，版本号从 2.0.3 改成 2.0.4
2. 执行打包命令，生成安装包 + latest.yml 文件
3. 把打包出来的文件上传到你的服务器（比如 http://172.16.19.122:8800/update/）
4. 用户打开旧版本的客户端
5. 客户端启动时自动请求服务器上的 latest.yml
6. 对比版本号，发现服务器上是 2.0.4，本地是 2.0.3
7. 弹出提示"有新版本"，用户点击"更新"
8. 客户端自动下载安装包，下载完自动安装
```

### 2.2 安装 electron-updater

```bash
npm install electron-updater
```

> **注意：** 项目里已经装过了（`package.json` 里有 `"electron-updater": "^6.1.7"`），不用重复装。

### 2.3 配置 electron-builder.yml 的 publish 部分

这是告诉 electron-updater "去哪里检查更新"的关键配置：

```yaml
# electron-builder.yml

# 其他配置...

publish:
  provider: generic # 使用通用 HTTP 服务器（不是 GitHub，不是 S3）
  url: http://172.16.19.122:8800/update # 你的更新文件存放地址
```

> **大白话解释：**
>
> - `provider: generic` → 意思是用一个普通的 HTTP 服务器来存放更新文件
> - `url` → 客户端启动后会去这个地址下载 `latest.yml`，看看有没有新版本
> - 这个地址下必须能访问到 `latest.yml` 文件和安装包文件

### 2.4 主进程里配置自动更新（完整代码直接抄）

```ts
// src/main/index.ts
import { autoUpdater } from "electron-updater";
import log from "electron-log/main";

// ====== 自动更新配置函数 ======
function setupAutoUpdater() {
  // 设置更新服务器地址（和 electron-builder.yml 里的 publish.url 保持一致）
  autoUpdater.setFeedURL({
    provider: "generic",
    url: "http://172.16.19.122:8800/update",
  });

  // 是否自动下载更新（true = 检测到新版本就自动下载，不等用户确认）
  autoUpdater.autoDownload = false;

  // 是否自动安装更新（true = 下载完自动退出并安装）
  autoUpdater.autoInstallOnAppQuit = true;

  // 日志输出到 electron-log
  autoUpdater.logger = log;

  // ====== 监听各种事件 ======

  // 检查更新出错（比如网络不通、服务器挂了）
  autoUpdater.on("error", (error) => {
    log.error("自动更新出错：", error);
    // 可以通知渲染进程显示错误提示
    mainWindow?.webContents.send("update-error", error.message);
  });

  // 正在检查更新
  autoUpdater.on("checking-for-update", () => {
    log.info("正在检查更新...");
  });

  // 检测到有新版本
  autoUpdater.on("update-available", (info) => {
    log.info("发现新版本：", info.version);
    // 通知渲染进程"有新版本可用"
    mainWindow?.webContents.send("update-available", {
      version: info.version, // 新版本号
      releaseDate: info.releaseDate, // 发布日期
      releaseNotes: info.releaseNotes, // 更新说明
    });
  });

  // 当前已是最新版本
  autoUpdater.on("update-not-available", (info) => {
    log.info("当前已是最新版本：", info.version);
    mainWindow?.webContents.send("update-not-available");
  });

  // 下载进度
  autoUpdater.on("download-progress", (progress) => {
    const percent = Math.round(progress.percent);
    log.info(`下载进度：${percent}%`);
    // 通知渲染进程显示进度条
    mainWindow?.webContents.send("download-progress", {
      percent: percent,
      bytesPerSecond: progress.bytesPerSecond,
      total: progress.total,
      transferred: progress.transferred,
    });
  });

  // 下载完成
  autoUpdater.on("update-downloaded", (info) => {
    log.info("更新下载完成：", info.version);
    // 通知渲染进程"下载完了，是否立即安装？"
    mainWindow?.webContents.send("update-downloaded", {
      version: info.version,
    });
  });
}

// ====== 在 app.whenReady() 里调用 ======
app.whenReady().then(() => {
  createWindow();

  // 等窗口加载完再检查更新（不然 mainWindow 可能还是 null）
  mainWindow?.webContents.on("did-finish-load", () => {
    // 生产环境才检查更新，开发环境不检查
    if (!is.dev) {
      setupAutoUpdater();
      autoUpdater.checkForUpdates();
    }
  });
});

// ====== 监听渲染进程的"开始下载"指令 ======
ipcMain.on("start-download", () => {
  autoUpdater.downloadUpdate();
});

// ====== 监听渲染进程的"立即安装"指令 ======
ipcMain.on("install-update", () => {
  // quitAndInstall 会退出应用并启动安装程序
  autoUpdater.quitAndInstall();
});

// ====== 监听渲染进程的"手动检查更新"指令 ======
ipcMain.on("check-for-update", () => {
  autoUpdater.checkForUpdates();
});
```

### 2.5 渲染进程（Vue 页面）怎么配合显示更新 UI

```vue
<!-- src/renderer/src/components/UpdateDialog.vue -->
<template>
  <el-dialog
    v-model="showUpdateDialog"
    title="发现新版本"
    :close-on-click-modal="false"
  >
    <div>
      <p>
        新版本号：<strong>{{ newVersion }}</strong>
      </p>
      <p>当前版本：{{ currentVersion }}</p>

      <!-- 下载进度条 -->
      <el-progress
        v-if="isDownloading"
        :percentage="downloadPercent"
        :status="downloadPercent === 100 ? 'success' : ''"
      />

      <!-- 更新说明 -->
      <div v-if="releaseNotes" class="release-notes">
        <h4>更新内容：</h4>
        <p v-html="releaseNotes"></p>
      </div>
    </div>

    <template #footer>
      <!-- 还没开始下载 -->
      <el-button
        v-if="!isDownloading && !downloadComplete"
        type="primary"
        @click="startDownload"
      >
        立即更新
      </el-button>
      <!-- 下载中 -->
      <el-button v-if="isDownloading" disabled>
        下载中... {{ downloadPercent }}%
      </el-button>
      <!-- 下载完成，等待用户确认安装 -->
      <el-button v-if="downloadComplete" type="primary" @click="installUpdate">
        安装并重启
      </el-button>
      <el-button @click="showUpdateDialog = false">稍后再说</el-button>
    </template>
  </el-dialog>
</template>

<script setup lang="ts">
import { ref, onMounted } from "vue";

const showUpdateDialog = ref(false);
const newVersion = ref("");
const currentVersion = ref("");
const releaseNotes = ref("");
const isDownloading = ref(false);
const downloadPercent = ref(0);
const downloadComplete = ref(false);

onMounted(() => {
  // 获取当前版本号
  window.api.invoke("get-app-version").then((version: string) => {
    currentVersion.value = version;
  });

  // 监听到有新版本
  window.api.on("update-available", (info) => {
    newVersion.value = info.version;
    releaseNotes.value = info.releaseNotes || "";
    showUpdateDialog.value = true;
  });

  // 监听下载进度
  window.api.on("download-progress", (progress) => {
    isDownloading.value = true;
    downloadPercent.value = progress.percent;
  });

  // 监听下载完成
  window.api.on("update-downloaded", () => {
    isDownloading.value = false;
    downloadComplete.value = true;
  });

  // 监听没有更新
  window.api.on("update-not-available", () => {
    // 可以在这里弹个"已是最新版本"的提示
    console.log("当前已是最新版本");
  });

  // 监听更新出错
  window.api.on("update-error", (errorMsg) => {
    console.error("更新出错：", errorMsg);
  });
});

// 开始下载
function startDownload() {
  isDownloading.value = true;
  window.api.send("start-download");
}

// 安装更新
function installUpdate() {
  window.api.send("install-update");
}
</script>
```

## NSIS 安装包目录配置——让用户装到你想让他装的地方

###  先搞懂默认行为

你打包出来的 `.exe` 安装包，默认行为是这样的：

- **默认安装位置：** `C:\Users\用户名\AppData\Local\Programs\my-app\`
- 文件夹名叫 `my-app`，是因为你 `electron-builder.yml` 里 `win.executableName` 写的是 `my-app`
- 默认装到 C 盘的用户目录下（不是 Program Files）
- 因为 `perMachine: false`，所以是"当前用户安装"，不需要管理员权限

> **大白话解释：**
>
> - `perMachine: false` → 只给当前登录的用户装，装在 `AppData\Local\Programs` 下，不用管理员权限
> - `perMachine: true` → 给这台电脑的所有用户装，装在 `C:\Program Files` 下，需要管理员权限

###  改安装文件夹的名字（不叫 my-app）

你觉得 `my-app` 这个名字太丑了，想改成"智能课堂"或者"ketang"，需要改两个地方：

**第一步：改 `electron-builder.yml` 的 `executableName`**

```yaml
# electron-builder.yml
win:
  executableName: ketang # ← 改这里！原来写的是 my-app
  icon: resources/icons/icon.ico
```

> 这个 `executableName` 决定了：
>
> 1. 打包出来的 exe 文件叫什么（`ketang.exe`）
> 2. 默认安装文件夹叫什么（`AppData\Local\Programs\ketang\`）

**第二步：同步修改 `installer.nsh` 里所有引用 exe 名字的地方**

因为你的项目有个 `installer.nsh` 自定义安装脚本，里面写死了 `my-app.exe`，改了名字必须同步：

```nsis
; installer.nsh
!macro customInstall
  WriteRegStr HKCU "Software\Classes\ketang-clients" "" "智能课堂系统字幕客户端"
  WriteRegStr HKCU "Software\Classes\ketang-clients" "URL Protocol" ""
  WriteRegStr HKCU "Software\Classes\ketang-clients\DefaultIcon" "" "$INSTDIR\\ketang.exe,1"
  WriteRegStr HKCU "Software\Classes\ketang-clients\shell\open\command" "" '"$INSTDIR\\ketang.exe" "%1"'
  ; ... 其他行也要把 my-app.exe 改成 ketang.exe
!macroend

!macro customUnInstall
  nsExec::ExecToLog 'taskkill /f /im "ketang.exe"'
  ; ... 其他行也要把 my-app.exe 改成 ketang.exe
!macroend
```

> **踩坑提醒：** 如果你只改了 `executableName` 没改 `installer.nsh`，安装的时候协议注册会指向一个不存在的 `my-app.exe`，导致协议唤起功能失效！

###  让用户自己选安装位置

你的项目里已经配好了：

```yaml
# electron-builder.yml
nsis:
  oneClick: false # 不是一键安装，会弹出安装向导
  allowToChangeInstallationDirectory: true # ← 允许用户自己选安装目录
```

这两个配置的效果是：用户双击安装包后，会弹出一个安装向导界面，里面有个"浏览"按钮，用户可以自己选择装到 C 盘还是 D 盘还是哪里。

> **大白话解释：**
>
> - `oneClick: false` → 如果设成 true，用户双击安装包就直接装了，啥都看不到，也没法选位置
> - `allowToChangeInstallationDirectory: true` → 安装向导里会出现"安装位置"那一步，用户可以改路径

###  设置默认安装到 D 盘（或其他盘）

如果你想让用户打开安装包的时候，默认路径就是 `D:\智能课堂\`，而不是 C 盘，那需要在 `installer.nsh` 里加一段 NSIS 脚本：

```nsis
; installer.nsh 顶部添加
!macro customInit
  ; 检查 D 盘是否存在，存在就默认装到 D 盘
  IfFileExists "D:\*" 0 +3
    StrCpy $INSTDIR "D:\智能课堂系统字幕客户端"
    Goto done
  ; D 盘不存在，检查 E 盘
  IfFileExists "E:\*" 0 +3
    StrCpy $INSTDIR "E:\智能课堂系统字幕客户端"
    Goto done
  ; 都没有，就用默认的 C 盘路径
  done:
!macroend
```

> **大白话解释：**
>
> - `customInit` 这个宏在安装界面显示之前执行
> - `$INSTDIR` 就是"默认安装路径"这个变量，你改它就等于改了默认路径
> - 上面这段逻辑是：优先装 D 盘 → D 盘没有就装 E 盘 → 都没有就装 C 盘
> - `IfFileExists "D:\*" 0 +3` → 检查 D 盘是否存在，不存在就跳过下面 3 行

### 强制安装到固定位置（不让用户改）

有些场景你希望强制装到某个目录，不给用户选择的机会：

```yaml
# electron-builder.yml
nsis:
  oneClick: true # 一键安装，不弹出向导
  allowToChangeInstallationDirectory: false # 不让用户改路径
  perMachine: true # 装到 Program Files（需要管理员权限）
```

或者用 `installer.nsh` 强制指定路径（用户连改的机会都没有）：

```nsis
!macro customInit
  StrCpy $INSTDIR "D:\智能课堂"
!macroend
```

###  perMachine 的区别（影响安装位置）

| 配置                | 默认安装路径                                     | 需要管理员权限 | 适用场景                     |
| ------------------- | ------------------------------------------------ | -------------- | ---------------------------- |
| `perMachine: false` | `C:\Users\用户名\AppData\Local\Programs\应用名\` | ❌ 不需要      | 普通用户软件（推荐）         |
| `perMachine: true`  | `C:\Program Files\应用名\`                       | ✅ 需要        | 系统级软件、需要所有用户共享 |

> **建议：** 一般用 `perMachine: false`，因为不需要管理员权限，用户装起来更顺畅，也不会被杀毒软件拦截。

### 5.8 安装路径相关的几个变量

在 `installer.nsh` 里可以用这些变量：

| 变量              | 含义               | 示例                                                                 |
| ----------------- | ------------------ | -------------------------------------------------------------------- |
| `$INSTDIR`        | 用户选择的安装目录 | `D:\智能课堂`                                                        |
| `$PROGRAMFILES`   | Program Files 目录 | `C:\Program Files`                                                   |
| `$PROGRAMFILES64` | 64位 Program Files | `C:\Program Files`                                                   |
| `$LOCALAPPDATA`   | 用户本地数据目录   | `C:\Users\lij\AppData\Local`                                         |
| `$APPDATA`        | 用户漫游数据目录   | `C:\Users\lij\AppData\Roaming`                                       |
| `$DESKTOP`        | 桌面路径           | `C:\Users\lij\Desktop`                                               |
| `$SMPROGRAMS`     | 开始菜单程序目录   | `C:\Users\lij\AppData\Roaming\Microsoft\Windows\Start Menu\Programs` |

### 5.9 卸载时自动关闭正在运行的程序

你的 `installer.nsh` 里已经有这段了，但这里解释一下为什么要加：

```nsis
!macro customUnInstall
  ; 卸载前先强制关掉正在运行的程序，不然文件被占用删不掉
  nsExec::ExecToLog 'taskkill /f /im "my-app.exe"'
!macroend
```

> **踩坑提醒：** 如果不加这个，用户在程序还开着的时候点卸载，会提示"文件被占用"，卸载失败，体验很差。
